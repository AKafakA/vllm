# vLLM Emulator Backend — User Guide

This guide explains how to run vLLM in **emulator mode** (GPU‑free cost oracle) using the current CLI flags and environment variables. It documents **existing behavior only**.

## When to use
- **Online (blocking) mode**: simulate real-time serving latency without a GPU.
- **Offline (non‑blocking) mode**: run analysis/throughput studies without wall‑clock sleeps.

## Quick start (CLI)
```bash
# Enable emulator mode with a profile pack
python -m vllm.entrypoints.openai.api_server \
  --model <your-model> \
  --emulator-mode online \
  --profile-pack examples/profiles/a100-sxm-80gb.json
```

## CLI Flags
| Flag | Values | Purpose |
|---|---|---|
| `--emulator-mode` | `online` \/ `offline` | Enable emulator mode. `online` sleeps for estimated latency; `offline` runs without blocking. |
| `--profile-pack` | path to JSON | Profile pack used by the GPU cost oracle (prefill/ decode samples). |

### Validation behavior
- `--emulator-mode` **requires** `--profile-pack` (or the corresponding env var).
- Setting `--emulator-mode` implicitly enables the oracle.

## Environment variables
These are read by the worker hook and are also **populated by CLI flags**:
- `VLLM_EMULATOR_ENABLE_ORACLE=1`
- `VLLM_EMULATOR_BLOCKING_MODE=online|offline`
- `VLLM_EMULATOR_PROFILE_PACK=/path/to/profile.json`

### Example (env‑only)
```bash
export VLLM_EMULATOR_ENABLE_ORACLE=1
export VLLM_EMULATOR_BLOCKING_MODE=offline
export VLLM_EMULATOR_PROFILE_PACK=examples/profiles/a100-sxm-80gb.json

python -m vllm.entrypoints.openai.api_server --model <your-model>
```

## Profile packs
Profile packs are JSON files containing prefill/decode latency samples for GPU compute.
- Examples: `examples/profiles/*.json`
- Generated by profiler scripts under `vllm_emulator/profiler/`

## Notes
- **Online mode** is suitable for serving simulations (e.g., OpenAI server).
- **Offline mode** is suitable for batch experiments (e.g., `LLM.generate`) and avoids sleep.
